MACAQUE MRI ATLAS -- PIPELINE TREE v5
Numbering is N.M.K. Every notebook cell header and function docstring cites the node it
implements, so a node number is a search key across all four notebooks and edge_fusion.py.
Comment markers [^cNN] are carried over unchanged from v2; the comment bodies are at the end.
Nodes marked (v3) are implemented but were absent from v2; (v4) likewise against v3; (v5)
likewise against v4.

v5 IN ONE PARAGRAPH. Junction identity used to be re-derived per subject, by clustering arc
endpoints within node_tol. node_tol was 1.0 voxel, which is exactly the spacing of the
half-integer lattice the trace puts junctions on, so a sub-voxel difference between two
subjects flipped a merge and changed the topology. 3.1.3.5 now stamps a junction id ONCE on
the template and 3.1.8 / 3.2.3.2 / 4.4.1 carry it, so 5.2.2.1 groups those ends by NAME and
only what the reviewer drew is still clustered by distance. node_tol is 0.1. 5.6.1.4 admits a
partially supported group as coverage only when a whole REGION is missing, which is what
orphan_region_policy (was orphan_policy) is actually for. 6.1.1 mirrors about the cut plane,
not H/2, and 6.1.2.1 is a hard gate. 3.1.10 is the audit that would have caught all of it.

- 3 Parcellation and Initial Export
  - 3.1 Parcellation
    - 3.1.1 Apply hemisphere mask (zeroes out right hemisphere)[^c8]
    - 3.1.2 (v3) Fragment relabelling
      - 3.1.2.1 A base region id that appears as several disconnected components in a slice
                is split into per-component fragment codes (ab#k)
      - 3.1.2.2 Runs BEFORE the voxel threshold, so arcs and seeds share one decomposition
      - 3.1.2.3 Fragments below the voxel threshold are dropped with their base region
      - 3.1.2.4 Region tables and SVG labels emit the fragment code, not the base id
    - 3.1.3 Trace boundaries into a graph
      - 3.1.3.1 (v4) Sub-threshold regions, TRIM_STAGE="raster"[^c9]: a piece below the voxel
                threshold is ABSORBED into the neighbour it shares the most boundary with, on
                the raster, before tracing. It is never turned into a background hole. A piece
                touching only background is the sole case that still goes to background
      - 3.1.3.2 Walk slice and record when voxels change regions
      - 3.1.3.3 Each segment records the two regions it separates
      - 3.1.3.4 Merge segments with same region boundaries into polylines
      - 3.1.3.5 (v5) JUNCTION IDENTITY. Once the template graph for a slice exists, every
                junction node is given a stable integer id. A node is a junction when its
                incident element count is not 2, or is 2 with different material pairs -- the
                SAME predicate 5.2.2 uses to end an arc, so the two can never disagree. The
                test reads element incidence and material codes only: there is no distance,
                radius or tolerance in it, so two junctions one voxel apart and two junctions
                a thousandth of a voxel apart are equally distinct. Ids are handed out in
                sorted coordinate order, so the same graph always yields the same ids
        - 3.1.3.5.1 (v5) The id is meaningful only because 3.1.7 gives every subject a COPY
                of one template graph. Ids assigned independently per subject would be
                unrelated numbers; 5.5.1.0.1 detects that case and discards them
        - 3.1.3.5.2 (v5) The id is carried by 3.1.8 (a 4th field on each N line), by 3.2.3.2
                (an optional _j<j0>_<j1> suffix on the arc's SVG id) and recovered by 4.4.1
    - 3.1.4 Smoothing and simplification
      - 3.1.4.1 Gaussian low-pass filter[^c10][^c11]
      - 3.1.4.2 Simplification via Douglas-Pecker algorithm
      - 3.1.4.3 (v3) Vertex budget: TRACE_MAX_VERTICES caps vertices per boundary by raising
                the Douglas-Peucker tolerance until the budget is met. Lossy; the worst
                deviation incurred is reported. None = NO LIMIT.
        - 3.1.4.3.1 (v4) TRACE_FORCE_VERTICES also ADDS vertices until the count matches the
                budget exactly. Lossless: every added vertex is the midpoint of an existing
                segment, so the curve does not move
      - 3.1.4.4 (v4) Sub-threshold regions, TRIM_STAGE="vector": the piece is kept through
                3.1.4 and then DISSOLVED onto its own centre line
        - 3.1.4.4.1 Exactly 2 neighbours (the sliver case): the two flanking arcs are
                resampled to a shared point count and averaged pointwise, giving one arc
                coded with the two neighbours, between the same two junctions
        - 3.1.4.4.2 3+ neighbours, where no midline is defined: the APPROXIMATE MEDIAL AXIS
                (interior Voronoi edges of the densely sampled boundary) is computed and each
                junction is joined to the medial-axis pole, giving one arc per junction coded
                with the two neighbours meeting there
        - 3.1.4.4.3 A closed island with one real neighbour is deleted, merging it into that
                neighbour. Anything else is left in place and reported
    - 3.1.5 Separate closed rings and open arcs[^c12]
    - 3.1.6 Compute seeds[^c13]
      - 3.1.6.1 (v3) A seed is the distance-transform maximum of the region's voxel mask
      - 3.1.6.2 (v3) Seeds are used only to break island / donut face ambiguities (5.7.3.3)
    - 3.1.7 Template graph identically applied to every slice
    - 3.1.8 Written as ASCII line file
      - 3.1.8.1 (v5) Each N line carries an optional 4th field, the 3.1.3.5 junction id
                (-1 = not a junction). A file without it still reads, and yields a graph with
                no junction ids at all
    - 3.1.9 (v3) Trace cache
      - 3.1.9.1 The trace is cached under a CACHE KEY of the label volume plus the trace
                parameters (including trim_stage, trace_max_vertices, trace_force_vertices),
                so changing any of them invalidates the cache instead of reusing it
    - 3.1.10 (v5) TRACE AUDIT. Diagnostic only; produces no pipeline output. Gated on
              AUDIT_REGION_COUNTS (0.4.4)
      - 3.1.10.1 Stage-to-stage: a region or fragment lost or gained, or a node added or
                deleted, between two consecutive checkpoints of ONE subject. Losses that
                3.1.3.1 or 3.1.4.4 caused on purpose are passed in as expected_lost and
                reported quietly; anything else is declared loudly
      - 3.1.10.2 Subject-to-subject: the same checkpoint compared across subjects
      - 3.1.10.3 (v5) JUNCTION CENSUS. 3.1.10.1/2 count VERTICES. Two subjects can carry
                identical vertex and element counts while their JUNCTION sets differ, which
                is the difference 5.5.1 fails on, so the junctions are censused separately:
                arc count, junction count, how many junctions still carry a 3.1.3.5 id, how
                many arc ends were absorbed by clustering, and the sorted multiset of
                incident region sets -- the key 5.5.1.1 will match on
      - 3.1.10.4 (v5) NODE_TOL MARGIN. The distance between the closest pair of distinct
                junctions, reported against node_tol, with a warning below a factor of 2. The
                trace puts junctions on a half-integer lattice, so this number is normally
                1.0 px and node_tol must sit well under it
      - 3.1.10.5 (v5) Subject-to-subject junction comparison: arc count, junction count,
                absorbed ends, region-set multiset and the carried id set must all agree
      - 3.1.10.6 (v5) FORCE_AUDIT_FOR_SLICES (0.4.8). 3.1.10.3 and 3.1.10.5 are per-slice and
                far too loud for a whole volume, so in FULL they run only for the slices
                listed there; 3.1.10.4 is one line per slice and always runs. TEST runs one
                slice and always reports everything
      - 3.1.10.7 (v5) Checkpoints: 1 post-3.1.2, 2 post-3.1.4.2, 3 post-3.1.4.4,
                4 post-3.1.7 (per subject), 5 post-3.2.6 (the re-imported graph, which is the
                object 5.1.2 actually receives)

- 5 Contour Fusion[^c18]
  - 5.1 Setup
    - 5.1.1 Load fusion parameters
    - 5.1.2 Load per-subject boundary graphs[^c19]
    - 5.1.3 Build seeds and expected region IDs
      - 5.1.3.1 Masked to chosen hemisphere
      - 5.1.3.2 (v3) Fragment canonicalisation: each subject's fragments are matched onto the
                template's fragments by centroid distance (fragment_match_tol_px), so the same
                anatomical component carries the same code in every subject
      - 5.1.3.3 Compute per-region seeds
      - 5.1.3.4 Compile list of non-zero region IDs present per-slice
  - 5.2 Constructing per-subject line network
    - 5.2.1 Normalize weights[^c20]
    - 5.2.2 Decompose per-slice graph into arcs[^c21] + nodes (first pass)
      - 5.2.2.1 Find arc endpoints within tolerance -> node junctions[^c22]
        - 5.2.2.1.1 (v5) An end carrying a 3.1.3.5 junction id is grouped by that ID and never
                by distance. Only ends with no id -- which after v5 means ends the REVIEWER
                created -- are clustered geometrically at node_tol. Topology therefore cannot
                change between subjects unless the reviewer changed it
        - 5.2.2.1.2 (v5) node_tol is 0.1 voxel, not 1.0. It is a COINCIDENCE tolerance (an
                Illustrator end that should touch but does not), never a feature scale: 1.0
                equalled the spacing of the half-integer junction lattice, so the merge
                decision sat on a knife edge and flipped between subjects
        - 5.2.2.1.3 (v5) Two ends weld only if their arcs SHARE a region. A junction is where
                regions meet, so two boundaries with no region in common cannot be one
                junction however close they pass
      - 5.2.2.2 Record closed island loops (no nodes)
  - 5.3 Inject phantom regions
    - 5.3.1 Verify all subjects that HAVE region R agree on its neighbour set -> disagreement
            is a complex case (halt)
    - 5.3.2 (v4) ONE template per region R, built from the subject with the MOST TYPICAL
            version of R: smallest total shape distance to the other subjects' versions of R.
            Chosen per region and independently of params.reference_sid, which is the
            arc-orientation reference of 5.6.1.1 and means something else.
            Every other subject that has R must agree with that one template on BOTH the
            neighbour SET and the CYCLIC ORDER of those neighbours (up to rotation and
            reversal, since subjects may trace in either direction). Any disagreement is a
            complex case; a second template is never built for a second arrangement
      - 5.3.2.1 Bounding arcs
      - 5.3.2.2 Neighbor codes (background counts as a neighbour)
      - 5.3.2.3 Ordered boundary cycle: arcs chained end-to-end around R -> cyclic neighbour
                order N_1 ... N_k and boundary junctions v_1 ... v_k
      - 5.3.2.4 Spoke per junction: the wall arc N_i|N_{i+1} at v_i (degree-4+ junction on R's
                boundary -> complex case, dedicated reason)
      - 5.3.2.5 (v4) Ambiguity is declared COMPLEX, never guessed. The LINE reduction looks
                its host border up across the WHOLE slice and requires it to be UNIQUE; where
                fragment relabelling cannot separate two borders carrying the same wall code,
                which one R collapses onto is undecidable and the slice stops. The TREE
                reduction still scopes its spoke/diagonal lookup to phantom_window_margin_px,
                but a non-unique spoke, or a far end its region sets do not distinguish, is
                complex rather than resolved by nearest-wins
    - 5.3.3 Reduce region R for addition to other subject(s)
      - 5.3.3.1 Island (all bounding arcs closed, <= 1 real neighbor) -> reduces to point
        - 5.3.3.1.1 Collapse R's boundary to a tiny copy at centroid/seed point (unchanged)
        - 5.3.3.1.2 The copy is given phantom_eps_px of length so its arcs survive dedup
      - 5.3.3.2 Lens (exactly 2 neighbors) -> reduces to line
        - 5.3.3.2.1 Project R onto other subject(s); cut the one host border where R's
                    junctions land, place new nodes
        - 5.3.3.2.2 Collapse R's boundary onto the host segment between the new nodes (unchanged)
      - 5.3.3.3 All other cases (3+ neighbors) -> reduces to a TREE (replaces the old cluster
                branch; cluster = tree with no diagonals)
        - 5.3.3.3.1 Pin each boundary junction v_i: find the spoke arc in the lacking subject,
                    take its endpoint that is NOT the far end -> pin point t_i (pinning rule)
        - 5.3.3.3.2 Collect the lacking subject's NEW arcs: walls between non-consecutive
                    neighbours (diagonals); verify they form a tree touching all pin points
                    (junctions = diagonals + 1, connected)
        - 5.3.3.3.3 Route each boundary arc R|N_i as the unique tree path from t_{i-1} to t_i
                    (may be zero-length when both pins coincide)
        - 5.3.3.3.4 Verify the double cover: every diagonal is traced by exactly two boundary
                    paths; no arc that is neither a spoke nor a collected diagonal ends at any
                    pinned junction
        - 5.3.3.3.5 Specially mark (label) each spoke's near end and each phantom arc end so
                    superimposed junctions stay distinct until after node fusion
        - 5.3.3.3.6 Add the phantom boundary arcs (zero-length, or arc-length-parametrized
                    copies of their tree paths)
        - 5.3.3.3.7 Absorb the diagonals: remove them from the lacking subject's arc set (their
                    geometry now lives inside the phantom arcs)
      - 5.3.3.4 Other (complex) cases -> Halts contour fusion for that slice (failure mode)
        - 5.3.3.4.1 Includes: spoke missing or ambiguous, new arcs not a tree, an arc that is
                    neither a spoke nor a collected diagonal ending at a pinned junction,
                    degree-4 junction on R's boundary in the template, adjacent missing-region
                    clusters, neighbour-set or cyclic-order disagreement (5.3.2)
        - 5.3.3.4.2 Records location of failure
        - 5.3.3.4.3 halt_on_situation3 stops the slice regardless of strict_topo; set False
                    only to survey how often the case occurs
    - 5.3.4 Output records of added phantom regions (kind: point / line / tree, with diagonal
            count), complex cases, and (v4) INDEPENDENT regions
      - 5.3.4.1 (v4) Situation 1: a region whose real neighbours are ALL absent from the
                lacking subject has no shared boundary anywhere to pin a phantom to, so it is
                carried through at full geometry instead of halting. Background is never
                counted as a neighbour for this test. A cluster with even ONE shared neighbour
                does not qualify: that member is complex on its own pass and stops the slice,
                so only clusters bounded entirely by background survive as independent
  - 5.4 Decompose updated per-slice graph into arcs[^c23] + nodes (second pass)
    - 5.4.1 Find arc endpoints within tolerance -> node junctions[^c24]
    - 5.4.2 Record closed island loops (no nodes)
    - 5.4.3 Phantom regions loudly declared
  - 5.5 Node fusion
    - 5.5.1 Match node junctions across subjects
      - 5.5.1.0 (v5) A junction that still carries its 3.1.3.5 id is paired by that id first.
                The id is identical across subjects by construction, so it needs neither a key
                nor a distance. An id carried by only SOME subjects means the reviewer removed
                or replaced that junction in the others, and is reported exactly like a
                region-set miss so 5.5.3 and 5.9 handle it unchanged
        - 5.5.1.0.1 (v5) INTEGRITY. A few ids disagreeing on their incident regions is a
                legitimate reviewer edit, and those ids alone fall back to 5.5.1.1. Wholesale
                disagreement means the graphs were numbered independently rather than copied
                from one template (3.1.3.5.1), so EVERY id is discarded and 5.5.1.1 takes over
                completely, with a warning
      - 5.5.1.1 Match through incident region sets
      - 5.5.1.2 Collisions resolved by Hungarian assessment[^c25] within a set displacement
      - 5.5.1.3 Phantom node junctions exempt from displacement requirement
    - 5.5.2 Averaging step
    - 5.5.3 End node fusion per-slice if any of the following occurs
      - 5.5.3.1 Any complex (non-autoresolvable) cases are present
      - 5.5.3.2 Node match rate is below a certain threshold
      - 5.5.3.3 There are any other conflicting/unmatched node junctions[^c26]
  - 5.6 Per-arc fusion (Edge fusion)
    - 5.6.1 Order subjects and incorporate weights
      - 5.6.1.1 Define reference subject (manual toggle, subject with most nodes, then least
                phantom regions, then first subject)[^c27][^c28]
      - 5.6.1.2 Starting with reference subject, pull other subjects' arcs and weights into
                shared space
      - 5.6.1.3 Renormalize weights per-arc[^c29]
        - 5.6.1.3.1 (v5) DEGENERATE WEIGHTS. A group supported only by zero-weight subjects
                is dropped rather than renormalised. Under the weighted Frechet mean a
                zero-weight element has no influence on the minimiser, so renormalising such
                a group to weight 1 would contradict the definition -- and did, which is why
                5.8.3 failed by construction under orphan_region_policy='passthrough'
      - 5.6.1.4 (v5) ORPHAN REGION TEST [F4]. A group that only some subjects have is
                COVERAGE only when a whole REGION is missing from the others -- Situation 1 of
                5.3.4.1, the case phantom injection deliberately leaves alone because there is
                no shared boundary to pin a phantom to. Every other partial group is a
                correspondence failure wearing coverage's clothes, and passing it through is
                what put two copies of the same boundary in the atlas
        - 5.6.1.4.1 PRESENCE: at least one of the arc's two codes must be a region the lacking
                subjects do not carry AT ALL
        - 5.6.1.4.2 WHOLENESS: the orphan arcs attributed to that region must be ALL of its
                arcs in every subject that has it, so the absence really is the region and not
                a few arcs the matcher lost
        - 5.6.1.4.3 REFUSAL: a group failing either test is a `fusion` failure (5.9.1.2), is
                dropped rather than emitted, and names which of the two tests it failed
        - 5.6.1.4.4 orphan_region_policy (v5, was orphan_policy) and min_region_support (v5,
                was min_arc_support) then decide what happens to a group that PASSED: keep it
                from the subjects that have it (passthrough), discard it (drop), or take the
                reference subject's version (reference)
    - 5.6.2 Orient arcs per-subject to[^c30] establish point-wise correspondence
      - 5.6.2.1 For island regions -> resample all copies to a common point count, force
                consistent winding (using signed area), and rotate (using FFT correlation)
                until start points line up
      - 5.6.2.2 For arcs -> force all arcs to run in the same direction as the reference
      - 5.6.2.3 Evaluate difference between forward and reverse orientations of each arc[^c31]
    - 5.6.3 Determine curvature per-point for every arc polyline
      - 5.6.3.1 Every arc polyline gets an ArcRep wrapper
      - 5.6.3.2 Stores working dense copy of arc internally
    - 5.6.4 Create anchor table per-arc (keypoints = True)[^c32]
      - 5.6.4.1 Determine keypoints
        - 5.6.4.1.1 Walk each arc's curvature to find local maxima of |curvature| above a
                    certain floor within a certain interval[^c33]
      - 5.6.4.2 Match keypoints
        - 5.6.4.2.1 Use a benefit matrix (two points must be close and at a similar point in
                    the arc) to propose assignments
        - 5.6.4.2.2 Solve matching with Hungarian algorithm[^c34]
      - 5.6.4.3 Add keypoints to anchor table
        - 5.6.4.3.1 Keypoints with 2+ matches get added
        - 5.6.4.3.2 Subjects missing an anchor get a replacement via linear interpolation
                    between existing anchors
      - 5.6.4.4 (v3) LABEL ANCHORS (the per-face points the QA text is placed at, NOT the
                intra-arc fusion anchors of 5.6.4 and not kp_anchors) are filtered to the
                largest fragment per base region when label_all_fragments is False
    - 5.6.5 Create anchor table per-arc (keypoints = False)
      - 5.6.5.1 Anchor table only returns [0, 1] (endpoints)
    - 5.6.6 Piecewise fusion between consecutive anchors
      - 5.6.6.1 Determine # of sample points between anchor intervals
        - 5.6.6.1.1 Take sagitta bound, resampling and growing until within tolerance or above
                    max samples permitted

    - 5.8.3 S7_sweep_identity: putting all weight on subject i must return that subject's own
            map
      - 5.8.3.1 (v5) WHY IT IS EXACT. Fusion is a weighted Frechet mean (Frechet 1948;
                Karcher 1977). In the convex-combination form of Ginestet, Simmons & Kolaczyk
                (2012), Definition 1, a A (+)_r b B lies in arginf_y [a d(A,y)^r + b d(y,B)^r];
                setting b = 0 leaves arginf_y a d(A,y)^r, whose minimiser is A. The identity is
                algebraic, not approximate, so any deviation measures only what the
                implementation adds
      - 5.8.3.2 (v5) The run therefore uses EXACT zero weights, not 1e-12, and 5.6.1.3.1 drops
                what the zero-weight subject alone supports
      - 5.8.3.3 (v5) The bound is the implementation's own error budget and nothing else:
                fit_tol_px (5.6.6.1 resamples to a sagitta bound of that size) + node_tol
                (5.2.2.1 places a junction at its cluster centroid and 5.6.8.1 snaps the arc
                end onto it). The old fit_tol*3 + node_tol/2 had no derivation
      - 5.8.3.4 (v5) The number is only meaningful on a slice with no 5.6.1.4.3 refusals: a
                refused arc leaves a hole, and the hole, not the averaging, is what the
                distance then measures
    - 5.8.4 M8 weight sweep: fused output tracked across the weight simplex
    - 5.8.5 Reference-subject ladder is exercised by S7_sweep_identity, not assumed
