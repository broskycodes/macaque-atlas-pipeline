- 2 Initial registration
  - 2.1 Affine transformation (subject -> template) using ANTs registration
    - 2.1.1 Confirm all files exist
    - 2.1.2 Estimate transform per-subject
      - 2.1.2.1 Initial alignment
      - 2.1.2.2 Coarse-to-fine optimization (rigid + affine)
      - 2.1.2.3 Similarity driven by MMI (Mattes Mutual Information)
    - 2.1.3 Emit registration products on template grid
      - 2.1.3.1 Forward and inverse transforms recorded
    - 2.1.4 Cache key
      - 2.1.4.1 A fingerprint of the template registered TO is stored beside each transform
      - 2.1.4.2 A cache built against a different template is rejected, not silently reused
  - 2.2 Score and gate
    - 2.2.1 Normalized cross-correlation between warped subjects and template
    - 2.2.2 Passes or warns per-subject based on threshold
    - 2.2.3 Normalised mutual information from a foreground-masked joint histogram
    - 2.2.4 Confirms warped shape = label shape
    - 2.2.5 Save transforms, warped scans, elapsed time, cache status
    - 2.2.6 Transform report
      - 2.2.6.1 Affine decomposed on template array axes
      - 2.2.6.2 Per-axis voxel step
      - 2.2.6.3 Occupancy extents
      - 2.2.6.4 Empirical volume scale vs the affine determinant
      - 2.2.6.5 Obliquity
      - 2.2.6.6 Return compact per-subject table (subject | det | total rotation | anisotropy |
                tilt | empirical-vs-det gap)
  - 2.3 Collapse to larger resolution in shared grid
    - 2.3.1 Determine target voxel size
      - 2.3.1.1 Maintain in-plane resolution, restore subjects' through-plane resolution
               (0.15mm x 0.15mm x 0.75mm)
    - 2.3.2 Build reference grid
      - 2.3.2.1 Resample template to reference grid
      - 2.3.2.2 New voxel count = old count x old spacing / new spacing, rounded
    - 2.3.3 Resample template labels
      - 2.3.3.1 Written onto reference grid with identity transform
    - 2.3.4 Resample each subject
      - 2.3.4.1 From original images, forward transform is applied onto the reference grid,
                collapsing into a single interpolation
    - 2.3.5 Record and verify the new grid and registration outputs
 
- 3 Parcellation and Initial Export
  - 3.1 Parcellation
    - 3.1.1 Apply hemisphere mask (zeroes out right hemisphere)
    - 3.1.2 Fragment relabelling
      - 3.1.2.1 A base region id that appears as several disconnected components in a slice
                is split into per-component fragment codes (ab#k)
      - 3.1.2.2 Runs BEFORE the voxel threshold, so arcs and seeds share one decomposition
      - 3.1.2.3 A fragment below the voxel threshold is dropped; other fragments of the same base
                region are unaffected
      - 3.1.2.4 Region tables and SVG labels emit the fragment code, not the base id
    - 3.1.3 Trace boundaries into a graph
      - 3.1.3.1 Sub-threshold regions, TRIM_STAGE="raster": a piece below the voxel
                threshold is ABSORBED into the neighbour it shares the most boundary with, on
                the raster, before tracing.
      - 3.1.3.2 Walk slice and record when voxels change regions
      - 3.1.3.3 Each segment records the two regions it separates
      - 3.1.3.4 Merge segments with same region boundaries into polylines
      - 3.1.3.5 Every junction given a stable, consistent ID, derived from the template graph. 
                Defined as any junction with incident element count >2 or =2 w/ different region pairs
    - 3.1.4 Smoothing and simplification
      - 3.1.4.1 Gaussian low-pass filter
      - 3.1.4.2 Simplification via Douglas-Pecker algorithm
      - 3.1.4.3 Vertex budget: raises the Douglas-Peucker tolerance until each boundary has at
                most N vertices. Lossy; worst deviation reported.
        - 3.1.4.3.1  TRACE_FORCE_VERTICES ADDS vertices until the count matches the
                  budget exactly. Adds vertexes such that curve doesn’t change
      - 3.1.4.4 Sub-threshold regions, TRIM_STAGE="vector": kept through
                3.1.4 and then DISSOLVED onto its own centre line
    - 3.1.5 Separate closed rings and open arcs
    - 3.1.6 Compute seeds
      - 3.1.6.1 A seed is the distance-transform maximum of the region's voxel mask
      - 3.1.6.2 Seeds are used only to break island / donut face ambiguities (5.7.3.3)
    - 3.1.7 Template graph identically applied to every slice, including standardized junction IDs
    - 3.1.8 Written as ASCII line file
      - 3.1.8.1 Junction IDs carried as a 4th field on each N line
    - 3.1.9 Trace cache
      - 3.1.9.1 The trace is cached under a cache key of the label volume plus the trace
                parameters, so changing either invalidates the cache instead of reusing it
    - 3.1.10 Confirm tracing is valid
      - 3.1.10.1 Stage-to-stage: a region or fragment lost or gained, or a node added or
                deleted, between two consecutive checkpoints of ONE subject, is declared
                loudly (unless passed as expected_lost during simplification)
       - 3.1.10.2 Repeat 3.1.10.2 across all subjects
       - 3.1.10.3 Stage-to-stage junction comparison: arc count, junction count,
                absorbed ends, region-set multiset and the carried id set must all agree
       - 3.1.10.4 Measure the distance between the closest pair of distinct junctions
                reported against node_tol (node_tol_margin), with a warning below a factor of 2.
       - 3.1.10.5 Repeat 3.1.10.3 across all subjects
  - 3.2 Export slices for correction
    - 3.2.1 Loads "warped" T1 as underlay
    - 3.2.2 Re-masks label slice to chosen hemisphere
    - 3.2.3 Write layered SVG
      - 3.2.3.1 Background (white + T1 raster)
      - 3.2.3.2 Boundaries (line vectors, emitted as junction-wise arcs)
       - 3.2.3.2.1 The arc's id becomes bnd_A_B_k_j<j0>_<j1> when both ends carry a
                junction id, which is the only attribute which Illustrator keeps
      - 3.2.3.3 Labels (annotations)
      - 3.2.3.4 Double-line export mode: each shared border is written as two
                coincident paths, one per owning region, so an expert can drag either side
                independently. The pair is collapsed back to one line on import (4.4.6).
    - 3.2.4 Write region reference table
    - 3.2.5 Output SVG
    - 3.2.6 Export/re-import verification gate
      - 3.2.6.1 The written SVG is re-imported and rejected unless every region code
                survives and the geometry error is within tolerance
    - 3.2.7 Auto-copy of exports into qc/ for review alongside the run's diagnostics

    - 4.4.2 _xHH_ escape sequences in ids are un-escaped before parsing

    - 4.4.6 Any double-line pairs (3.2.3.4) are collapsed back to a single line
 
- 5 Contour Fusion
  - 5.1 Setup
    - 5.1.1 Load fusion parameters
    - 5.1.2 Load per-subject boundary graphs
    - 5.1.3 Build seeds and expected region IDs
      - 5.1.3.1 Masked to chosen hemisphere
      - 5.1.3.2 Fragment canonicalisation: each subject's fragments are matched onto the
                template's fragments by centroid distance (fragment_match_tol_px), so the same
                anatomical component carries the same code in every subject
      - 5.1.3.3 Compute per-region seeds
      - 5.1.3.4 Compile list of non-zero region IDs present per-slice
  - 5.2 Constructing per-subject line network
    - 5.2.1 Normalize weights
    - 5.2.2 Decompose per-slice graph into arcs + nodes (first pass)
      - 5.2.2.1 Find arc endpoints within tolerance -> node junctions
       - 5.2.2.1.1 Ends grouped by region ID, not by distance. Arcs without standardized IDs 
                (created during QA) are clustered geometrically at node_tol.
       - 5.2.2.1.2* Ends only weld if their arcs SHARE a region.
      - 5.2.2.2 Record closed island loops (no nodes)
  - 5.3 Inject phantom regions
    - 5.3.1 Verify all subjects that HAVE region R agree on its neighbour set -> disagreement
            is a complex case (halt)
    - 5.3.2 One template (reference) built per region R, using “most typical” version (smallest total
            shape difference to other subjects’ R if present); every R-present subject must agree on 
            region set and cyclic correspondence. 
      - 5.3.2.1 Bounding arcs
      - 5.3.2.2 Neighbor codes (background counts as a neighbour)
      - 5.3.2.3 Ordered boundary cycle: arcs chained end-to-end around R -> cyclic neighbour
                order N_1 ... N_k and boundary junctions v_1 ... v_k
      - 5.3.2.4 Spoke per junction: the wall arc N_i|N_{i+1} at v_i (degree-4+ junction on R's
                boundary -> complex case)
      - 5.3.2.5 Cases declared complex: The LINE reduction looks its host border up
                across the WHOLE slice and requires it to be UNIQUE; fragment relabelling
                cannot separate two borders carrying the same wall code, which one
                R collapses onto is undecidable. For TREE, non-unique spokes, or a far
                end undistinguished by region sets is designated complex (for time being)
    - 5.3.3 Reduce region R for addition to other subject(s)
      - 5.3.3.1 Island (all bounding arcs closed, <= 1 real neighbor) -> reduces to point
        - 5.3.3.1.1 Collapse R's boundary to a tiny copy at centroid/seed point (unchanged)
        - 5.3.3.1.2 The copy is given phantom_eps_px of length so its arcs survive deduplication
      - 5.3.3.2 Lens (exactly 2 neighbors) -> reduces to line
        - 5.3.3.2.1 Project R onto other subject(s); cut the one host border where R's
                    junctions land, place new nodes
        - 5.3.3.2.2 Collapse R's boundary onto the host segment between the new nodes (unchanged)
      - 5.3.3.3 All other cases (3+ neighbors) -> reduces to a TREE (replaces the old cluster
                branch; cluster = tree with no diagonals)
        - 5.3.3.3.1 Pin each boundary junction v_i: find the spoke arc in the lacking subject,
                    take its endpoint that is NOT the far end -> pin point t_i (pinning rule)
        - 5.3.3.3.2 Collect the lacking subject's NEW arcs: walls between non-consecutive
                    neighbours (diagonals); verify they form a tree touching all pin points
                    (junctions = diagonals + 1, connected)
        - 5.3.3.3.3 Route each boundary arc R|N_i as the unique tree path from t_{i-1} to t_i
                    (may be zero-length when both pins coincide)
        - 5.3.3.3.4 Verify the double cover: every diagonal is traced by exactly two boundary
                    paths; no arc outside the spoke and diagonal sets may terminate at a pinned junction
        - 5.3.3.3.5 Specially mark (label) each spoke's near end and each phantom arc end so
                    superimposed junctions stay distinct until after node fusion
        - 5.3.3.3.6 Add the phantom boundary arcs (zero-length, or arc-length-parametrized
                    copies of their tree paths)
        - 5.3.3.3.7 Absorb the diagonals: remove them from the lacking subject's arc set (not present
                    in subjects(a) A, so they must be removed)
      - 5.3.3.4 Other (complex) cases -> Halts contour fusion for that slice (failure mode)
        - 5.3.3.4.1 Includes: spoke missing or ambiguous, new arcs not a tree, foreign arc at a
                    pinned junction, degree-4 junction on R's boundary in the template,
                    adjacent missing-region clusters
        - 5.3.3.4.2 Records location of failure
        - 5.3.3.4.3 halt_on_situation3 stops the slice regardless of strict_topo; set False
                    only to survey how often the case occurs
    - 5.3.4 Output records of added phantom regions (kind: point / line / tree, with diagonal
            count) and complex cases
     - 5.3.4.1 A region whose real neighbours are ALL absent from the lacking subject
                has no shared boundary anywhere to pin a phantom to, so it is carried through
                with unchanged geometry instead of halting. 
  - 5.4 Decompose updated per-slice graph into arcs + nodes (second pass)
    - 5.4.1 Find arc endpoints within tolerance -> node junctions
    - 5.4.2 Record closed island loops (no nodes)
    - 5.4.3 Phantom regions loudly declared
  - 5.5 Node fusion
    - 5.5.1 Match node junctions across subjects
     - 5.5.1.1 Junctions are paired by their IDs first. An id carried by only SOME subjects means 
                is reported exactly like a region-set miss (see 5.5.3, 5.9 handling).
        - 5.5.1.1.1 If some but not all junction IDs disagree on their incident regions (due to reviewer 
                edits), node matching occurs via 5.5.1.1.2 for those junctions alone. If “wholesale 
                disagreement” occurs, junction IDs are deleted and 5.5.1.1.2 takes over.
        - 5.5.1.1.2* Match through incident region sets as a fallback to 5.5.1.1.
      - 5.5.1.2 Collisions resolved by Hungarian assessment within a set displacement
      - 5.5.1.3 Phantom node junctions exempt from displacement requirement
    - 5.5.2 Averaging step
    - 5.5.3 End node fusion per-slice if any of the following occurs
      - 5.5.3.1 Any complex (non-autoresolvable) cases are present
      - 5.5.3.2 Node match rate is below a certain threshold
      - 5.5.3.3 There are any other conflicting/unmatched node junctions
  - 5.6 Per-arc fusion (Edge fusion)
    - 5.6.1 Order subjects and incorporate weights
      - 5.6.1.1 Define fusion reference subject (manual toggle, subject with most nodes, then least
                phantom regions, then first subject)
      - 5.6.1.2 Starting with reference subject, pull other subjects' arcs and weights into
                shared space
      - 5.6.1.3 Renormalize weights per-arc
       - 5.6.1.3.1 Groups supported only by zero-weight subjects are dropped rather than
                  renormalised.
     - 5.6.1.4 Partial coverage and passthrough only occurs when an entire region is missing from
                some subjects, these are the criteria for an arc to be considered “partial coverage”
       - 5.6.1.4.1 At least one of the arc's two codes must be a region the lacking
                  subjects do not carry AT ALL
        - 5.6.1.4.2 Isolated arcs attributed to that region must be ALL of its arcs in every
                  subject that has it, the absence must consist of the entire region
        - 5.6.1.4.3 Failing either test escalates the isolated arcs to a `fusion` failure (5.9.1.2),
                dropping them, and naming where it failed.
        - 5.6.1.4.4 orphan_region_policy and min_region_support determine orphaned region
                logic: keep from subjects which have it (passthrough), discard it (drop), or take the
                reference subject's version (reference)
    - 5.6.2 Orient arcs per-subject to establish point-wise correspondence
      - 5.6.2.1 For island regions -> resample all copies to a common point count, force
                consistent winding (using signed area), and rotate (using FFT correlation)
                until start points line up
      - 5.6.2.2 For arcs -> force all arcs to run in the same direction as the reference
      - 5.6.2.3 Evaluate difference between forward and reverse orientations of each arc
    - 5.6.3 Determine curvature per-point for every arc polyline
      - 5.6.3.1 Every arc polyline gets an ArcRep wrapper
      - 5.6.3.2 Stores working dense copy of arc internally
    - 5.6.4 Create anchor table per-arc (keypoints = True)
      - 5.6.4.1 Determine keypoints
        - 5.6.4.1.1 Walk each arc's curvature to find local maxima of |curvature| above a
                    certain floor within a certain interval
      - 5.6.4.2 Match keypoints
        - 5.6.4.2.1 Use a benefit matrix (two points must be close and at a similar point in
                    the arc) to propose assignments
        - 5.6.4.2.2 Solve matching with Hungarian algorithm
      - 5.6.4.3 Add keypoints to anchor table
        - 5.6.4.3.1 Keypoints with 2+ matches get added
        - 5.6.4.3.2 Subjects missing an anchor get a replacement via linear interpolation
                    between existing anchors
      - 5.6.4.4 Label anchors are filtered to the largest fragment per base region when
                label_all_fragments is False
    - 5.6.5 Create anchor table per-arc (keypoints = False)
      - 5.6.5.1 Anchor table only returns [0, 1] (endpoints)
    - 5.6.6 Per-segment averaging between consecutive anchors
      - 5.6.6.1 Determine # of sample points between anchor intervals
        - 5.6.6.1.1 Take sagitta bound, resampling and growing until within tolerance or above
                    max samples permitted
        - 5.6.6.1.2 Label "saturated" if the bound is outside tolerance even with max samples
        - 5.6.6.1.3 Output max chords required among subjects
      - 5.6.6.2 Resample each subject's segment with # of sample points
        - 5.6.6.2.1 Place points by arc length (lambda = 0)
        - 5.6.6.2.2 Place points by curvature (lambda = 1)
        - 5.6.6.2.3 Place points by a blend of both methods (0 < lambda < 1)
      - 5.6.6.3 Take weighted pointwise mean of all sample points
    - 5.6.7 Concatenate fused per-sample segments into arc polylines
      - 5.6.7.1 Drop duplicate anchors to avoid double counting
    - 5.6.8 Snap arc endpoints to fused nodes
      - 5.6.8.1 Distribute required correction linearly along the arc
      - 5.6.8.2 Identical points are merged
  - 5.7 Polygon construction
    - 5.7.1 Prepare arcs
      - 5.7.1.1 Drop degenerate arcs
      - 5.7.1.2 Remove duplicate geometry
      - 5.7.1.3 Snap dangling ends to nodes within tolerance
        - 5.7.1.3.1 Repetition of 5.6.8.1 for geometry added post-fusion; passthrough orphans, 
                phantom arcs, mirrored arcs (6.1), and imported expert geometry
        - 5.7.1.3.2* Correction is distributed linearly over the arc's own arc-length
                parameterisation (like 5.6.8.1)
        - 5.7.1.3.3* An end with no node inside dangle_repair_px cannot be attached: it is
                a `post-fusion` failure, fusion stops for that slice, and it goes to 5.9
    - 5.7.2 Polygonize arcs
      - 5.7.2.1 Count interior arc crossings
      - 5.7.2.2 Split arcs at crossings
      - 5.7.2.3 Produce faces using polygonize
      - 5.7.2.4 If error arises, try un-noded, then rebuild one ring per region (won't
                represent holes, not ideal)
       - 5.7.2.4.1 (v4) Reaching chainer_fallback is a `polygonize` FAILURE, not a degraded
                success: its one-ring-per-region output cannot represent holes, so the slice
                stops and goes to 5.9
    - 5.7.3 Assign faces to regions
      - 5.7.3.1 A face bounded by arcs takes the common region ID
      - 5.7.3.2 Neighbor rule is used to resolve island / donut pairs
      - 5.7.3.3 Use distance-transform seed to decide ambiguities
      - 5.7.3.4 Everything else is given an UNLABELED designation and region ID
    - 5.7.4 Update per-slice registry
      - 5.7.4.1 Base-rollup rule: fragment codes are converted back to their base region id in
                the registry, so a region that fragments differently between slices becomes
                one registry entry
    - 5.7.5 Rebuild per-subject atlases (for diagnostics if enabled)
    - 5.7.6 Output polygons as atlas
  - 5.8 Diagnostics
    - 5.8.1 S1-S5 pipeline-correctness checks (run whenever fusion runs)
    - 5.8.2 S6/S7 comparative shape metrics, gated on run_comparative_diag because they force
            one atlas rebuild PER SUBJECT
      - 5.8.2.1 M1 round_dev, M2 peri_dev, M6 topo_delta (free once the shared unions exist)
      - 5.8.2.2 M3' avg_gl protrusion preservation (metrics_avg_gl)
      - 5.8.2.3 M7 curvature-distribution KS test (metrics_curv_ks)
      - 5.8.2.4 M4 skeleton/hull ratio (metrics_skele)
      - 5.8.2.5 diag_ignore_unlabeled excludes 8001+ and 9001+ ids from S6/S7 only
    - 5.8.3 S7_sweep_identity: putting all weight on subject i must return that subject's own map
      - 5.8.3.1 Any deviation measures what the implementation added (error bound)
      - 5.8.3.2 Exact zero weights are used (no floating point min values)
      - 5.8.3.3 Acceptable bound is the implementation's own error budget: fit_tol_px + node_tol
      - 5.8.3.4 Only meaningful on a slice where no arcs have been dropped (affects identity test)
    - 5.8.4 M8 weight sweep: fused output tracked across the weight simplex
    - 5.8.5 Reference-subject ladder is exercised by S7_sweep_identity, not assumed
 - 5.9 Post-fusion reviewer round-trip (TEST/FULL notebooks)
    - 5.9.1 Four failure points, each stopping the slice after EVERY failure in that stage has
            been collected
      - 5.9.1.1 topological (5.3): a region absence phantom injection cannot resolve (complex)
      - 5.9.1.2 fusion (5.6.8.1): an arc end that cannot be attached to its fused node
                within snap_max_px; and (5.6.1.4.3) a partially supported group which is
                dropped, not an orphan region. 
       - 5.9.1.3 post-fusion (5.7.1.3): a dangling end with no node inside dangle_repair_px
       - 5.9.1.4 polygonize (5.7.2.4): polygonize failed noded AND un-noded
    - 5.9.2 A topological failure (5.9.1.1) exports ONE SVG PER SUBJECT (overlaid on subject 
            scans), where any necessary edits are made, and a color-coded superimposition of all 
            subjects (BLUE for R-present, RED for R-absent) as a visual aid. 
    - 5.9.3 All other failures export ONE SVG of the FUSED lines without a subject underlay
    - 5.9.4 Output tree: RUN_DIR/postqa_review/<failure point>/slice_<NNN>/ holding the 
            SVG(s) and failures.txt, which lists every failure point on that slice and why it failed.
            The failure-point folders are topological, fusion, post-fusion and polygonize.
    - 5.9.5 The reviewer edits the SVG in place; the next run reads it back, repeats the stage
            that failed, and either continues or raises again. Reporting fusion errors, taking
            the fix back in, continuing, and then reporting separate post-fusion or polygonize
            errors is the expected sequence.
    - 5.9.6 All slices must pass one failure point before the run moves on to the next series of 
            checks, so the run always reports the earliest failing stage across every
            slice. halt_on_failure=False can be enabled for reporting only
    - 5.9.7 Diagnostics reflect the FINAL product only.
 
- 6 Conversion to volumetric model
  - 6.1 Mirror Hemisphere back for Bilateral Symmetry
    - 6.1.1 Reflect kept-hemisphere graph across the L-R midline
     - 6.1.1.1 Axis of reflection is the cut plane, defined as H/2 - 0.5 (corrects int rounding error)
      - 6.1.1.2* Arcs lying ENTIRELY on the midline are deleted before arcs_to_graph
                so polygonize produces one face spanning both hemispheres. 
        - 6.1.1.2.1* Only goes into effect if all points are within MIRROR_WELD_TOL of the 
                  midline and the arc contains a real region in its code, preserving near-midline 
                  boundaries between different regions.
    - 6.1.2 Weld the reflection to the original at the midline
      - 6.1.2.1 Merge coincident nodes along the midline seam
       - 6.1.2.1.1 Zero shared seam nodes imply the two halves are disjoint
                graphs that merely touch, forces a hard stop. 
      - 6.1.2.2 Drop duplicated midline arcs so that faces can merge across the center
    - 6.1.3 Rebuild full-brain faces from the welded graph
    - 6.1.4 Ensure same region IDs on both hemispheres
    - 6.1.5 Fragments are merged back to their base region ids before mirroring, so the
            volume carries anatomical ids and not per-slice fragment codes
  - 6.2 Rasterize polygonized atlas into a labeled volume
    - 6.2.1 Load template label volume for grid dimensions and affine
    - 6.2.2 Allocate an empty int16 volume, set background ID to zero
      - 6.2.2.1 1-999 template regions, 8001-8999 UNLABELED, 9001-9999 expert-drawn,
                10001-31999 fragments. A fragment code is 10000 + (j-1)*1000 + base, where
                base = (code-10000) % 1000 and j = (code-10000)//1000 + 1.    
      - 6.2.2.2 Due to int16 numbering constraints, the pipeline cannot accommodate
                more than 22 fragments of one region, or a base id over 999.         
    - 6.2.3 Per-Slice Work
      - 6.2.3.1 Merges every multi-polygon into single list of polygons
      - 6.2.3.2 Sort each polygon face by area in descending order
